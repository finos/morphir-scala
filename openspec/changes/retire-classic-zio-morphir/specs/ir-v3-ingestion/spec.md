# Spec Delta

## Purpose

Lets a Kyo-based consumer load the Morphir IR that morphir-elm produces (`morphir-ir.json`, format version 3) into the
code model, without the classic ZIO-based library, and holds that reader to the shared Morphir Compatibility Kit.

## ADDED Requirements

### Requirement: Decode a v3 library distribution into the code model
The system SHALL decode a `morphir-ir.json` document whose `formatVersion` is 3 and whose distribution is a `Library`
into a code-model library distribution with the same package name, dependencies, modules, types and values.

#### Scenario: Package contents survive decoding
- **WHEN** a v3 library document is decoded
- **THEN** every module, type definition, constructor, value definition and documentation string in the document is
  present in the distribution under the same fully qualified name

#### Scenario: Real morphir-elm output
- **WHEN** the v3 documents in the MCK IR kit that were generated by morphir-elm are decoded
- **THEN** decoding succeeds for each of them

### Requirement: Conform to the MCK IR suite for v3
The system SHALL pass every non-pending `@version:3` case in the IR suite of the Morphir Compatibility Kit embedded in
the pinned Morphir CLI, for each node kind the adapter claims.

#### Scenario: MCK run
- **WHEN** `morphir mck run --suite ir` runs against the project's adapter
- **THEN** the report shows no failed `@version:3` case and passes `morphir mck report check`

#### Scenario: Unclaimed cases are skipped, not passed
- **WHEN** the kit holds a case for a version or node kind the adapter does not claim
- **THEN** the report records that case as skipped

### Requirement: Provide an MCK IR adapter
The project SHALL provide an executable that answers the MCK IR adapter protocol, claims format version 3 and the
node kinds the reader supports, decodes with the v3 reader and writes canonical v3 output.

#### Scenario: Capabilities
- **WHEN** the runner sends `capabilities`
- **THEN** the adapter answers with version 3, the `json` profile, the `single` layout and its supported node kinds,
  and claims no other format version

#### Scenario: Decode round trip
- **WHEN** the runner sends `decode` with a v3 input for a claimed node kind
- **THEN** the adapter answers with that node's canonical v3 JSON spelling

### Requirement: Erase attributes the code model cannot hold
The system SHALL erase v3 type and value attributes, except that a typed value's type SHALL become the code-model
value's inferred type.

#### Scenario: Typed value keeps its type
- **WHEN** a value in the document carries a type as its attribute
- **THEN** the decoded expression records that type as its inferred type

#### Scenario: Untyped attribute is dropped
- **WHEN** a value or type carries a non-type attribute
- **THEN** the decoded node has empty attributes

### Requirement: Produce a deterministic order
The system SHALL order decoded constructors and bundle libraries by name, so that decoding the same document twice, or
two documents that differ only in key order, yields equal results.

#### Scenario: Constructor order does not depend on input order
- **WHEN** two documents list the same custom type's constructors in different orders
- **THEN** both decode to the same constructor sequence

### Requirement: Expand a bundle into libraries
The system SHALL decode a v3 `Bundle` distribution as one code-model library distribution per package it contains,
ordered by package name.

#### Scenario: Bundle with two packages
- **WHEN** a document's distribution is a `Bundle` holding two packages
- **THEN** decoding yields two library distributions, ordered by package name

### Requirement: Reject unsupported input with a typed error
The system SHALL fail with a typed error, not an exception, when the document is not valid JSON, is not a v3
distribution, or has a `formatVersion` other than 3. The error SHALL name the problem and its location, and SHALL use
the MCK diagnostic code where the kit names one for that rejection.

#### Scenario: Older format version
- **WHEN** a document declares `formatVersion` 1 or 2
- **THEN** decoding fails with an error that names the unsupported format version

#### Scenario: Kit rejection case
- **WHEN** the MCK kit requires a v3 reader to reject an input with a named diagnostic
- **THEN** the adapter's rejection carries that diagnostic code

#### Scenario: Malformed document
- **WHEN** the input is truncated JSON or has an unknown node tag
- **THEN** decoding fails with an error that identifies the fault and where it occurs

### Requirement: No classic library or ZIO at runtime
The v3 reader SHALL run without the classic `org.finos.morphir` IR types and without ZIO on its runtime classpath, on
every platform it is published for.

#### Scenario: Runtime classpath
- **WHEN** the runtime classpath of the module that provides the reader is resolved on each published platform
- **THEN** it contains no ZIO artifact and no classic morphir artifact
