Observed runtime profiles

The external sampler polls at 50 ms plus measurement cost. It includes the host parent and its workers, excluding Mill, the compiler and sampler. Aggregate RSS is the simultaneous process sum, which double-counts shared resident pages. It is not physical memory. Missing samples remain null. Short call bursts can fall between polls.

RSS probe cost per sample: median 3.45 ms, maximum 47.29 ms. This is sampling work duration, not a measured total application slowdown. The separate no-sampler runs have no observation holds. Phase events still record heap/GC counters, so no claim of zero instrumentation overhead is made. Fresh-process trials do not flush OS or runtime caches; cache-cold machine startup was not measured. Extism's optional system compilation-cache configuration was not separately instrumented.

Warm-call summaries pool 500 measured calls across five fresh processes after discarding each process's ten recorded warm-up calls. Per-call ranges show observations, not confidence intervals.

First-result timestamps follow one successful export/byte exchange or one real MEP compile, before the recorded 10 warm-up and 100 measured calls. Per-call nanoseconds are retained in worker results. Native builds use O2, compatibility CPU and default Serial GC. JVM runs use the pinned JDK's defaults; collector names/counts/times and runtime heap counters are in phase events. The historical raw field heapCommittedBytes records Runtime.totalMemory(), a runtime-reported heap capacity, not measured OS committed or resident memory. Heap used is totalMemory minus freeMemory; heapMaxBytes is Runtime.maxMemory(). Native Image can report a large capacity while RSS remains small. Endive's available linear-memory size is retained at loaded and calls-complete markers. GraalWasm includes Truffle runtime compilation. No forced GC or NMT is enabled in baseline profiles. Heap counters exclude third-party native allocation; reserved virtual memory and exact native allocation attribution were not collected. Fully instrumentation-free startup timing is unavailable; the no-RSS-sampler timings retain phase events.

Component and CLI verdicts

None of the six configurations is component-qualified. Endive 1.2.0's release account places Component Model, WIT bindgen and Canonical ABI work in the companion endive-cm repository. Companion APIs and async components remain unverified here. Pinned GraalWasm options expose core-Wasm/WASI P1 facilities, not a component result from this experiment. Extism's selected C plugin ABI is a core-Wasm interface; no WIT/component adapter was exercised.

Remaining blockers

The pinned portable MoonBit source build is blocked by an installed compiler/core mismatch. Its receipt and build log are retained without substituting a synthetic guest. FFM needs an actual absolute memory-ceiling solution. GraalWasm needs a bounded loading path for these guests. MCK pass/fail and independent report-check results are retained per ABI and guest; guest-corpus success is narrower than full independent host conformance. Production discovery, installation and CLI migration require a separate change.

Kyo FFI RC7 generation rejected pointer-bearing callback arguments. The experiment therefore uses direct JDK FFM. C layout evidence is retained separately. Native packaging is target-specific to macOS arm64.
